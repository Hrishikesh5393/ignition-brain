# Ignition 8.1 → 8.3 traps

Tables of what was removed, deprecated, silently changed, renamed or newly added between
8.1 and 8.3. Split verbatim from `whats-new-8.3.md` (the feature narrative, release notes
and upgrade path stay there). Check this file before trusting any Ignition knowledge that
could be 8.1-era.

## Removed and deprecated

### Removed outright

| Removed | Notes |
|---|---|
| **Hot swapping of modules** | *"Hot swapping modules is no longer supported in Ignition 8.3. You will need to restart your Gateway if you want to install or upgrade a module."* |
| **Agent Recovery EAM task** | *"The Agent Recovery EAM task has been removed from Ignition 8.3. You can still use other agent tasks to perform a similar operation."* |
| **Serial Support Client / Serial Support Gateway modules** | Bundled into the Ignition platform; `system.serial` migrated in. Still may appear as separate license items. |
| **Web Browser module** | Bundled into Vision; component now under Misc. |
| **x86 macOS launcher support** | Mac launchers are Apple Silicon only. |
| **Old Perspective theme entry-point files** | *"The old entry point files that existed at the root of the themes folder have been removed."* |
| **XY Chart `bullets.height` / `bullets.width`** | Removed in 8.3.5, replaced by `bullets.radius`. |
| **Multi-Instance Wizard "List of Names" pattern type** | Removed in 8.3.0 — and **restored in 8.3.9**. |
| **Gateway Control Utility (GCU)** | Now in the Deprecated manual; `gwcmd` is the supported path. |

**Other deprecations:**

* `system.dataset.toPyDataSet` — *"deprecated because datasets no longer need to
  be manually wrapped as PyDatasets."* Related: `system.dataset.toDataSet`
  became **`system.dataset.toDataset`** (lowercase `s`) with a single syntax.
  This is a silent breaker for anyone matching on the old capitalisation.
* `system.net.httpGet` / `httpPost` / `httpPut` / `httpDelete` → use
  `system.net.httpClient`.
* Expression function **`forceQuality`** → `qualifiedValue`.
* Designer **Project Properties > Perspective > General > Identity Provider**
  → use **Project Properties > Project > General**.
* Perspective Table **`pager.initialOption`** → new `option` property, which
  *"improves on the deprecated property by honoring external writes even after
  the table initializes."*
* **Custom Tag History Aggregates** — *"originally intended to be a workaround
  to older SQL historian schema limitations. This feature is only supported when
  used with the legacy `system.tag.queryTagHistory` and
  `system.tag.queryTagCalculations` functions, which are also deprecated."*
* **Create Project Permission** Gateway setting — deprecated in **8.3.7** in
  favour of the existing Designer Permissions / Role(s) settings.

### Behaviour changes that silently break 8.1 assumptions

1. **Anonymous OPC UA clients lose write and call.** *"anonymous (not logged in)
   OPC UA clients will no longer have write and call access to devices and Tag
   Providers by default... this change also applies to any device or Tag
   Provider without explicit role mappings defined."*
2. **New OPC UA client and server certificates are generated on upgrade** and
   must be re-trusted at both ends.
3. **Audit Profile table/column capitalisation changed.** `AUDIT_EVENTS` /
   `AUDIT_EVENTS_ID` in 8.1 are `audit_events` / `audit_events_id` in 8.3.
   *"which can cause SQL queries to fail when new 8.3 installs connect to 8.1
   databases with existing Audit Profiles"* — an in-place upgrade preserves the
   old formatting, a fresh install does not.
4. **Store and Forward Max Records → 0 (unlimited)** on upgrade.
5. **Gateway permissions do not carry over** from 8.1 and must be re-assigned;
   some setting names also changed.
6. **`Require Two Way Auth` defaults to True**, so a new backup node in a
   redundant pair will fail to connect until it mirrors the master's setting.
7. **`Allow Java Serialization`** is auto-enabled on upgrade and off on fresh
   installs — mixed fleets that add a *new* 8.3 Gateway must turn it on manually.
8. **Historical paths using `drv:` break for the Core Historian.**
9. **Tag file paths can exceed the Windows 255-character limit.**
10. **Duplicate usernames block upgrade.** *"Ignition 8.3 Gateways do not allow
    users in Internal or AD/Internal Hybrid User Sources to have the same
    username."* If you upgrade without cleaning them, *"you will need to restore
    your 8.1 Gateway, remove the duplicate users and upgrade again."*
    Since 8.3.4 the migration detects, logs and **skips** such user sources
    rather than corrupting them — the user source simply will not be there.
11. **VOIP call-script locale collisions.** Locale serialization moved from
    Apache Commons to Java language tags; `nn_NO_NY` and `nn_NO` both become
    `nn-NO`, so *"one of the records will fail to migrate."*
12. **`Iec61850ReportEntryIds` data is not migrated**, deliberately, to avoid
    duplicate-data quarantine.
13. **Cross-major-version tag editing is unsupported.** *"Editing tag
    configurations originating from a different major Ignition version is not
    supported."* Editing an 8.3 remote provider's tags from an 8.1 Designer
    throws `GatewayException` / `UndeclaredThrowableException`.
14. **`GATEWAY_MODULES_ENABLED` containers break** until MariaDB / MSSQL /
    PostgreSQL JDBC drivers are added by their new module identifiers.
15. **Perspective File Upload silently caps at 20 MB** regardless of
    `fileSizeLimit`.
16. **`Intl.NumberFormat` replaced Numeral.js** (8.3.3) — formatted number
    output can differ per locale.
17. **IEC 61850 addressing changed in 8.3.9.** Attributes shared by multiple
    Functional Constraints are now separate OPC nodes with an `[FC]` suffix.
    *"Tags on affected addresses must be re-addressed after upgrading."*
