# IEC 61850 Substation & Power-System Modelling

**Standard:** IEC 61850 — communication networks and systems for power utility automation.
Key parts: **-5** (communication requirements), **-6** (SCL / `.icd`/`.scd` config files),
**-7-1/-7-2** (basic information & abstract communication model — ACSI), **-7-3** (common data
classes), **-7-4** (compatible logical node classes and data objects), **-7-420** (DER logical
nodes), **-8-1** (MMS mapping), **-9-2** (Sampled Values), **-90-7** (inverter-based DER),
**-90-9** (battery energy storage). This doc is the **global / universal** layer — principle
only. Whether *this* deployment uses 61850 and how it maps is in
the project gateway profile and
the project UDT catalogue.

## The data model — four nested levels

IEC 61850 models a device as a strict hierarchy (IEC 61850-7-1 / -7-2):

| Level | What it is | Example |
|-------|------------|---------|
| **Physical Device (IED)** | The box on the network, one IP address | a protection relay, a meter, an inverter controller |
| **Logical Device (LD)** | A functional grouping inside the IED | `CTRL`, `PROT`, `MEAS`, `LD0` |
| **Logical Node (LN)** | One standardised function, 4-letter class + instance number, optional prefix | `MMXU1`, `PTOC1`, `Q0_XCBR1` |
| **Data Object (DO)** | A standardised piece of information on that LN (a "common data class" from -7-3) | `MMXU1.TotW`, `XCBR1.Pos` |
| **Data Attribute (DA)** | A leaf value inside the DO, often nested | `.stVal`, `.q`, `.t`, `.mag.f`, `.ctlVal` |

**Object reference syntax:** `LDName/LNName.DOName.DAName` (with further `.SDO.DA` nesting for
structured DOs), e.g. `RELAY1PROT/PTOC1.Op.general` or `MTR1MEAS/MMXU1.TotW.mag.f`.

The first letter of the LN class encodes the function group: **M** metering/measurement,
**P** protection, **X** switchgear, **C** control/switch-controller, **T** instrument
transformers, **Y** power transformers, **Z** other power-system equipment, **R** protection-
related (recloser, fault locator), **G** generic, **D** DER, **L** system (`LLN0`, `LPHD`),
**S** sensors/monitoring, **I** interfacing/archiving, **A** automatic control.

### Common DAs and functional constraints (FC)

| DA | Meaning | FC |
|----|---------|----|
| `stVal` | status value (enum/bool) | ST |
| `mag.f` / `cVal.mag.f` | analog magnitude (float) | MX |
| `q` | quality flags (validity, source, test…) | ST/MX |
| `t` | timestamp of last change | ST/MX |
| `ctlVal` | control value to write | CO |
| `setMag.f`, `setVal` | settings / setpoints | SP / SG |

FC (ST status, MX measurand, CO control, SP setpoint, CF/DC config/description) partitions the
same LN's data by role — it matters when mapping to tags because it tells you read-only vs
writable and static vs live.

## Protocols in one paragraph

**MMS** (ISO 9506, IEC 61850-8-1) — client/server over TCP/IP; how a SCADA/gateway reads
values, receives buffered/unbuffered **reports**, and issues **control** (select-before-operate
or direct-operate). This is the mapping Ignition uses via a 61850 driver/module.
**GOOSE** (IEC 61850-8-1) — fast layer-2 multicast on the substation LAN for trip signals and
interlocking between IEDs, sub-4 ms, with retransmission; normally *not* consumed by SCADA
directly. **SV / Sampled Values** (IEC 61850-9-2, "9-2LE") — multicast streaming of digitised
CT/VT instantaneous samples from merging units to protection; real-time bus traffic, not a
SCADA data source. A gateway integrates 61850 by acting as an **MMS client**; GOOSE/SV stay on
the process/station bus.

## When IEC 61850 applies

> **Applies when the gateway integrates equipment that natively speaks 61850, or when the
> customer/utility mandates the 61850 data model.** In practice:
>
> | Use 61850 modelling | Plain OPC-UA / PLC modelling is enough |
> |---------------------|----------------------------------------|
> | Utility-scale / transmission / distribution substations | Behind-the-meter C&I sites, no utility interconnect requirements |
> | Grid-tied generation with an interconnect agreement (utility-scale PV, wind, BESS) | Small DER with a simple PLC/inverter Modbus or OPC interface |
> | Protection relays, IEDs, merging units in scope | No protection devices; PLC-based control only |
> | An `.scd` / `.icd` file is part of the deliverables | Vendor gives you a Modbus/OPC register map |
> | GOOSE/SV on a station bus | Single control network, polled I/O |
>
> When it doesn't apply, model the equipment per [`isa95.md`](./isa95.md) +
> [`iec-61131.md`](./iec-61131.md) and skip the 61850 structure.

## Reflecting 61850 structure in an Ignition UDT — principle

When 61850 *does* apply, preserve the object model so the tag path round-trips to the IED
reference. Concrete UDT shapes are in
the project UDT catalogue.

| 61850 element | Ignition mechanism | Principle |
|---------------|--------------------|-----------|
| IED | UDT instance (one per device), or a device folder | Instance carries the IED name / IP as parameters. |
| Logical Device | Nested UDT member, or a folder segment | One LD → one sub-structure; keep the `LD` name in the path. |
| Logical Node | Nested UDT (`MMXU`, `XCBR` as reusable member types) | An `MMXU` UDT is defined once and reused for every metering LN. |
| Data Object | Nested UDT / member folder | `Pos`, `TotW` become sub-structures holding their DAs. |
| Data Attribute (`stVal`, `mag.f`, `q`, `t`) | Atomic tags — OPC-mapped where live, memory where derived | Keep `q` and `t` alongside the value; don't discard 61850 quality. |
| FC (ST/MX/CO/SP) | Read-only vs writable tag config; control tags grouped | Control DOs (`ctlVal`) get write permission + audit; measurands stay read-only. |
| Datasets / report control blocks (`LLN0`) | Driver/module config, not tags | Reporting is configured in the connection, surfaced as tag subscriptions. |

Datatype of each leaf follows [`iec-61131.md`](./iec-61131.md) (e.g. `mag.f` → Float,
`stVal` enum → Integer, `q` → Integer bitfield or String, `t` → DateTime).

## agent rules

> - **Confirm whether 61850 is in scope from
>   the project gateway profile before modelling
>   power equipment.** If it isn't, use plain OPC-UA / ISA-95 modelling.
> - **When it is in scope, derive structure from the IED's SCL file (`.icd`/`.cid`/`.scd`)**, not
>   from memory — LN/DO catalogues vary by edition and vendor.
> - **Preserve the `LDName/LNName.DOName.DAName` path** in the Ignition tag path so a tag maps
>   unambiguously back to the IED reference.
> - **Keep `q` (quality) and `t` (timestamp) DAs** as tags next to the value — 61850 quality is
>   richer than Ignition's and operators/protection engineers rely on it.
> - **Control DOs (`ctlVal`, FC=CO) are write points** — grant write permission narrowly, log
>   the operation, respect select-before-operate. See [`iec-62443.md`](./iec-62443.md).
> - **Don't try to consume GOOSE or SV in the gateway** — the gateway is an MMS client only.
> - Reuse LN-level UDTs (`MMXU`, `XCBR`) rather than one giant device UDT — see
>   [`udt-design.md`](./udt-design.md).
