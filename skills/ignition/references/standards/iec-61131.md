# IEC 61131 Control Logic

**Standard:** IEC 61131 — programmable controllers. **Part 3** (IEC 61131-3, currently Ed. 3,
2013) defines the programming languages, the common elements, and the **elementary data types**
(IEC 61131-3 Ed. 3 §6.3 / Table 10–11) and identifier rules (§6.1). Part 9 covers IO-Link
(SDCI). This doc is the **global / universal** layer — it constrains how a agent types tags
and writes bindings. Field-specific prefix conventions this site adopts go in
the project naming convention.

The point: **a value coming from a PLC must land in an Ignition tag whose type preserves its
range, sign, and precision.** A silent truncation or sign flip in a tag is a defect that
surfaces months later as a "sensor glitch".

---

## Elementary data types → OPC-UA → Ignition

IEC 61131-3 elementary types, their exact width/range, the OPC-UA built-in type a driver
normally exposes them as, and the **Ignition tag data type** that preserves the value.

| IEC 61131-3 | Bits | Range | OPC-UA type | Ignition tag type | Notes |
|-------------|------|-------|-------------|-------------------|-------|
| `BOOL` | 1 | 0 / 1 | Boolean | **Boolean** | — |
| `BYTE` | 8 | bit string | Byte (unsigned) | **Short** (Int2) | bit-string, treat as unsigned 0–255 |
| `WORD` | 16 | bit string | UInt16 | **Integer** (Int4) | unsigned 0–65535 |
| `DWORD` | 32 | bit string | UInt32 | **Long** (Int8) | unsigned 0–4.29e9 |
| `LWORD` | 64 | bit string | UInt64 | **Long** (Int8) | ⚠ values > 2^63−1 overflow Java `long` |
| `SINT` | 8 | −128 … 127 | SByte | **Short** (Int2) | Ignition Byte/Int1 is signed but small; Short is safe |
| `INT` | 16 | −32768 … 32767 | Int16 | **Short** (Int2) | exact |
| `DINT` | 32 | −2 147 483 648 … 2 147 483 647 | Int32 | **Integer** (Int4) | exact — Ignition's `Integer` is 32-bit signed |
| `LINT` | 64 | −2^63 … 2^63−1 | Int64 | **Long** (Int8) | exact |
| `USINT` | 8 | 0 … 255 | Byte | **Short** (Int2) | won't fit signed Int1 |
| `UINT` | 16 | 0 … 65535 | UInt16 | **Integer** (Int4) | won't fit signed Int2 |
| `UDINT` | 32 | 0 … 4 294 967 295 | UInt32 | **Long** (Int8) | won't fit signed Int4 |
| `ULINT` | 64 | 0 … 2^64−1 | UInt64 | **Long** (Int8) | ⚠ upper half overflows |
| `REAL` | 32 | IEEE 754 single (~7 sig. digits) | Float | **Float** (Float4) | do **not** promote silently to Double — you fabricate precision |
| `LREAL` | 64 | IEEE 754 double (~15–16 sig. digits) | Double | **Double** (Float8) | exact |
| `STRING` | n×8 | single-byte chars | String | **String** | encoding is driver/PLC dependent |
| `WSTRING` | n×16 | 2-byte / Unicode chars | String | **String** | — |
| `CHAR` / `WCHAR` (Ed. 3) | 8 / 16 | one character | Byte / UInt16 | **String** or **Integer** | — |
| `TIME` / `LTIME` | — | duration | often Double (ms) or String — driver-specific | **Long** or **String** | *unverified:* exact OPC mapping varies by driver |
| `DATE`, `TIME_OF_DAY`/`TOD`, `DATE_AND_TIME`/`DT` | — | calendar / clock | DateTime (for DT) | **DateTime** or split fields | `DATE` and `TOD` alone often come across as strings |

**Ignition has no unsigned integer types.** Every unsigned PLC type must go up one Ignition
width. Ignition scalar numeric types are Int1 (signed 8-bit "Byte"), Int2 ("Short"),
Int4 ("Integer"), Int8 ("Long"), Float4 ("Float"), Float8 ("Double") — all signed, backed by
Java primitives. *(Confirm the exact type-name strings against an extracted `schema/` artifact
or a live `get_tag_config` read before relying on them in a resource JSON.)*

### Signed vs unsigned pitfalls

| Trap | What happens | Fix |
|------|--------------|-----|
| `UINT` counter mapped to Ignition `Short` | reads correct 0–32767, then **wraps to −32768** at 32768 | map `UINT` → `Integer` |
| `DWORD` status word mapped to `Integer` | bit 31 set → value reads negative; bitwise expressions misbehave | map `DWORD` → `Long`, mask explicitly |
| `REAL` (Float4) auto-widened to `Double` in a UDT member or expression | UI shows `72.30000305...` — the extra digits are quantisation noise, not data | keep it Float; round for display only |
| Rockwell `SINT`/`INT` used as a packed bit array | reading it as a number loses per-bit meaning | expose individual bits or use `BYTE`/`WORD` → bit-address child tags |
| PLC `LREAL` totaliser mapped to `Float` | precision collapses; large totals lose the fractional part | map `LREAL` → `Double` |
| Scaled analog (`INT` raw 0–27648, Siemens) treated as engineering units | value off by the scaling factor | apply the raw→EU scale in the tag or OPC, document it |

## Identifier rules — IEC 61131-3 vs Ignition

| | IEC 61131-3 (§6.1.2) | Ignition tag / UDT names |
|--|----------------------|--------------------------|
| Allowed characters | letter / digit / single underscore; must start with letter or underscore | broad — letters, digits, spaces, most punctuation; **not** `\ / ` and control chars; `.` and `/` are path separators so avoid in a name |
| Underscores | leading OK, single embedded OK; **no double `__`, no trailing `_`** | any |
| Case | **case-insensitive** — `Motor_1` == `MOTOR_1` == `motor_1` | **case-sensitive** — those are three different tags |
| Length | standard requires ≥ 6 significant chars; vendors allow more (Rockwell 40, TIA up to 128). *unverified:* exact per-vendor limits | long paths allowed but keep segments short for binding readability |
| Leading digit | not allowed | allowed but avoid |

**The case-sensitivity mismatch is the sharp edge.** If a PLC export and a hand-typed tag differ
only in case, the PLC treats them as one symbol and Ignition treats them as two. Pick one
casing convention and generate tags from the PLC symbol table where possible.

## Field naming vocabulary (informative — not from the standard)

Common in the field; the scheme this site picks is in
the project naming convention.

| Style | Example | Seen in |
|-------|---------|---------|
| Hungarian-ish type prefix | `bRunning` (BOOL), `iCount` (INT), `diTotal` (DINT), `rFlow` (REAL), `sRecipe` (STRING), `stMotor` (struct/UDT), `arrTemps` (array), `xEStop` (bit) | Beckhoff / CODESYS, Siemens SCL |
| Structured-Text dotted access | `Motor01.Cmd.Start`, `Tank.PV`, `Valve[3].Fault` | any ST/FBD codebase, mirrors UDT members |
| Rockwell tag + member | `Mtr_101.Sts.Run`, `AI_PT_100` | Studio 5000 / Logix |
| Siemens absolute (avoid symbolic-free) | `%DB10.DBX0.0`, `%I0.1`, `%MW20` | S7 / TIA — always prefer the symbolic name |
| ISA-5.1 loop-tag roots | `FT`, `PT`, `TT`, `LT`, `FIC`, `PV`, `SP`, `CV` | instrument tags, P&ID-derived |

Prefix conventions describe **datatype or signal role**, not the ISA-95 path — keep the two
concerns separate (path = folders + UDT params, see [`isa95.md`](./isa95.md)).

## When this applies

> **Every time a agent creates a tag that reads from a PLC or OPC server, defines a UDT
> member type, or writes an expression/binding that does arithmetic or bit operations on a PLC
> value.** Also when importing a PLC tag export, generating tags from a symbol table, or
> reviewing someone else's tag build. Not relevant for pure-Ignition memory tags, derived
> metrics with no PLC origin, or Perspective-only state.

## agent rules

> - **Match the Ignition tag type to the PLC type using the table above — never eyeball it.**
>   When unsure of the source type, read it (`get_tag_config` / `browse_tags` on a *narrow*
>   subtree, or the PLC export), don't guess.
> - **Every unsigned PLC type goes up one Ignition width** (`UINT`→Integer, `UDINT`→Long). Flag
>   `ULINT`/`LWORD` values that can exceed 2^63−1 — Ignition can't hold them.
> - **Keep `REAL` as Float and `LREAL` as Double.** Widening Float→Double fabricates precision;
>   narrowing Double→Float destroys it.
> - **Treat status/command words (`BYTE`/`WORD`/`DWORD`) as unsigned bit strings.** Map wide
>   enough, mask bits explicitly, don't let sign bits leak.
> - **Assume PLC identifiers are case-insensitive; assume Ignition tags are case-sensitive.**
>   One casing convention, generated from the symbol table where possible.
> - **Raw-vs-engineering-units scaling is a decision, not a default** — apply it in the tag/OPC
>   and document it, or carry the raw value with the scale as tag properties.
> - Cross-check the folder/UDT structure against [`isa95.md`](./isa95.md) and
>   [`udt-design.md`](./udt-design.md); naming against [`tag-naming.md`](./tag-naming.md).
